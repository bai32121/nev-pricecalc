## 车价计算器（自建，替代 GitHub 现成项目）

**背景**：用户想装一个 GitHub 上的「车价计算器」开源项目。实测搜索（中英文多轮）结论：无成熟项目。
- 中文关键词（车贷计算器/购车计算器/落地价/养车成本）结果全是 README 全文匹配噪音；最优结果 star ≤ 25
- 英文最好的是 `tooladda-online/car-loan-calculator`(24★，纯静态 EMI)，`blackkcold/tools-bar`(1★，含房贷车贷的工具集)

**结论**：用户选择自建。产物 `车价计算器.html`（工作区根目录，单文件、零依赖、双击即用）。

**关键实现**
- 购置税：裸车 ÷ 1.13 × 10%；新能源按 2026.1.1–2027.12.31 减半征收（实征 5%），减免上限 1.5 万/辆 → `full - min(full*0.5, 15000)`
- 真实年化：现金流 IRR（期初到手 = 贷款额 − 金融服务费 − 强制装潢，逐期月供折现），**年化用 m×12（APR 口径）**，这样无杂费时恰好等于名义利率 3.60%，可直接对比；若用 (1+m)^12−1 会多出 0.06 个点，误导用户以为被收费
- 等额本金总利息 = loan × r × (n+1)/2（已用 node 单测校验，与摊还表一致）
- 5 年总账中第 1 年保险已在落地价内，养车只计 4 年续保，避免重复计算
- 方案对比写入 localStorage（key `carprice.plans.v2`，上限 6 条）
- 已做 CSS 变量 + 浅色主题、1280/窄屏适配、右侧 sticky 内滚动（避免长卡片被裁）

**验证方式**：把计算核心用 `// ==== CORE START/END ====` 标记包起来，用 Python 正则抽出后用 node 跑 8 组用例（IRR、等额本息/本金、购置税三档、0 首付 0 利率、全款）；再用 Edge headless 截图肉眼校验三轮 + 注入脚本查 scrollWidth 确认无横向溢出。

**踩坑**：Edge headless 的 `--window-size` 与 `document.documentElement.clientWidth` 差约 47px，截图会比真实视口窄，导致右侧被"看起来裁掉"——排查溢出要用 JS 比对 scrollWidth/clientWidth，别信截图边缘。

## 迭代三：实付 / 净支出口径拆分 + 方案折叠

**修掉一处口径 bug**：原 `land` 直接减了补贴，`upfront = land - loan + 费用` 也就把补贴扣掉了，与实际"提车当天全额垫付"的现金流不符（说明文字与数字自相矛盾）。现拆成三套口径：
- `payLand = 裸车 + 税 + 险 + 上牌 + 装饰 + 充电桩`（**实付落地价**，票面全额）
- `land = payLand - subsidy`（**补贴到账后净支出**，最终真正花掉的钱）
- `cashToday = payLand - loan + finFee + forceDecor + deposit`（提车当天现金）；`cashNet = cashToday - subsidy`
- `year1` 用 `cashNet` 口径，与净支出统一；`total5` 维持净口径不变
- UI：右栏顶部两列并排（`实付落地价` 黑色 / `补贴到账后净支出` 绿色），中间虚线；<560px 自动竖排。明细末尾加「合计」行 = 净支出，绿色。「提车现金」加一行「补贴到账后相当于退回 −¥15,000」

**方案对比改为折叠卡片**（原来的横向表格在 >4 条时挤不下）：
- `.plan` + `.plan-head`（车型/实付/补贴后/月供/删除）+ `.plan-body`（15 格明细，3 列；窄屏 2 列）
- 折叠动画用 `grid-template-rows: 0fr → 1fr`（比 max-height 准，无需估高度）
- 展开态存在内存 `openSet{id:1}`；保存时**清空 openSet 只展开新存的那条**，否则连存多条会全部展开
- 头部按钮「全部展开 / 全部收起」按 `plans.every(p => openSet[p.id])` 切换文案
- 删除按钮用 `e.target.closest('button[data-del]')` 且**先判断再判 head**，否则点删除会同时触发展开
- head 用 `div[role=button][tabindex=0]` 而非 `<button>`（内部还要放删除按钮，button 不能嵌套）
- 老方案数据兼容：`loadPlans()` 里补 `id` 与 `payLand = land + (subsidy||0)`，key 仍为 v3，不丢历史

**窄屏踩坑**：Edge headless 有**最小视口宽度 461px**，`--window-size=414` 时 clientWidth 仍是 461，截图按 414 输出 → 右侧被裁，看着像溢出其实不是。要测真窄屏得用 `<iframe width=390>` 包一层（需 `--allow-file-access-from-files` 才能跨 file:// 读 contentDocument）。
**窄屏真 bug**：`.card-h` 里标题被 hint/按钮挤成两行、"清空"竖排 → media 里 `flex-wrap:wrap` + `h2{margin-right:auto;white-space:nowrap}` + `.hint{order:10;flex-basis:100%}` + `button{white-space:nowrap}`。

## 打包成 exe（2026-10-31 18:00）

**技术选型**：Python 3.13 + pywebview（WinForms + Edge WebView2 内核）+ PyInstaller onefile → 13.1 MB 单文件，免安装。环境已有 WebView2 运行时 141，无 dotnet/cargo。

**关键坑 1：pythonnet 无 cp313 wheel** → `pip install pythonnet` 会去源码编译（内部调 nuget 更新，必然失败）。解法：`--only-binary :all:` 强制二进制，拿到 pythonnet 3.2.1 的 cp313 wheel，之后 pywebview 才装得上。

**关键坑 2：localStorage 必须固定 origin**。方案数据存在 localStorage，origin 一变全丢。所以：
- ❌ 不能读 `_MEIPASS` 里的临时 HTML（每次启动路径都变）
- ❌ 不能用 `http_server=True`（端口随机 → origin 带端口，每次都变）
- ✅ 首次运行把 HTML 复制到 `%LOCALAPPDATA%\NEVPriceCalc\app.html`（路径固定），用 `file://` 加载，并固定 `storage_path=...\profile`、`private_mode=False`
- 已实测：A 进程点「保存为方案」→ B 进程读回同一条，跨进程持久化成立

**关键坑 3：PyInstaller 参数**。必须 `--collect-all webview`（否则缺 `Microsoft.Web.WebView2.Core.dll` / `WebView2Loader.dll`）+ `--collect-all clr_loader --collect-all pythonnet --hidden-import clr --copy-metadata pythonnet`。

**其他实现**：
- 单实例：`CreateMutexW` 命名互斥体，`GetLastError()==183` 时 `FindWindowW + ShowWindow(SW_RESTORE) + SetForegroundWindow` 拉前一个窗口再 exit(0)。否则两个进程抢同一个 WebView2 user data 目录会锁死。
- 窗口几何存 `window.json`（closing 事件里读 `win.width/height/x/y/state`），下次还原；`state==1` 表示最大化。
- `--windowed` 没有控制台，异常写 `last_error.log` + `MessageBoxW` 弹窗，否则用户只看到"双击没反应"。

**验证手段**：
- 起窗口后 `FindWindowW(None, "新能源车价计算器")` 轮询
- `ImageGrab.grab` 会被前台窗口遮挡干扰、`SetForegroundWindow` 常被系统拒绝 → 改用 `PrintWindow(hwnd, mdc, 2)`（PW_RENDERFULLCONTENT）抓窗口自身画面，Chromium 系窗口可靠
- 已确认：窗口 1260×940、页面完整渲染、二次启动后窗口数仍为 1 且第二进程 exit 0、window.json 正确写入

## 图标缓存问题（18:25–18:35）

用户反馈「文件夹上还是显示旧图标」。排查结论：**exe 本身没问题，是 Windows 图标缓存**。

**验证链条**：
1. `find . -name "*.exe"` 只有两份（根目录 + dist），mtime 都是 18:19，均晚于 ico 的 18:18 → 确认是重新打包的产物
2. 解 ico 逐尺寸逐个 byte 在 exe 里 find，8 档全部命中
3. `SHGetFileInfoW(path, 0, &shfi, sizeof, SHGFI_ICON)` → 拿到 hIcon，再用 `CreateDIBSection + DrawIconEx` 画到 bitmap → 渲染出蓝底白车的新图标

**踩坑**：
- `SHGetFileInfoW` 在沙箱内首次调用返回 0 / `GetLastError=1008`(ERROR_NO_TOKEN) —— 必须先定义 `argtypes/restype`，且要用 `ctypes.WinDLL("shell32", use_last_error=True)`；不定义 argtypes 时 str 参数不会转成 LPCWSTR，API 直接失败
- 用 `wt.HICON` 而不是 `c_void_p`，sizeof(SHFILEINFO) = 696
- `taskkill /F /IM explorer.exe` 后，大部分 iconcache_*.db 会被系统合并清理，只剩 16/32/48/idx；但 `os.remove` 被平台的 safe-delete 拦截（走回收站失败），**缓存文件实际删不掉**
- 受限环境下不必强删：explorer 重启后按「文件 mtime 与缓存项比对」逐项校验，exe 时间变了就会重新提取图标。仅重启 explorer + `SHChangeNotify(SHCNE_ASSOCCHANGED/SHCNE_UPDATEITEM)` + `ie4uinit -show` 足够
- `explorer.exe /select,<中文路径>` 在此环境不生效（会落到「文档」或「此电脑」），传参要用 `/select,"path"` 作**单个参数**；中文路径仍会被 explorer 忽略，故最终放弃截图验证，改用 SHGetFileInfo 取图标

**结论**：用户侧按 F5 或重开文件夹即可；任务栏固定项需取消固定后重新固定。

## 打包 Android APK（19:18–19:30）

用户要 "再做成 .apk"。环境原本没有 JDK / Android SDK / Gradle，全部现装到 `tools/`（便携式，不动系统）：
- `tools/jdk-17.0.20.1+1`（Temurin，清华镜像，304 MB）
- `tools/android-sdk`（cmdline-tools + platform-tools + build-tools;34.0.0 + platforms;android-34，448 MB）

**关键决策：不走 Gradle，手工串官方工具链**（`android/build.py`）：
```
aapt2 compile --dir res -o res.zip
aapt2 link -o unsigned.apk -I android.jar --manifest ... -A assets --java gen --auto-add-overlay res.zip
javac -encoding UTF-8 -source 8 -target 8 -classpath android.jar -d classes ...java
d8.bat --lib android.jar --min-api 24 --output dex classes/**/*.class
zipfile 追加 classes.dex -> apk
zipalign -f -p 4 -> apksigner sign -> verify
```
好处：没有 Maven 依赖、3 秒出包、完全可复现；代价是 R.java 和 dex 合并要自己管。产出 254 KB。

**WebView 壳设计**（`android/app/src/com/nev/pricecalc/MainActivity.java`）：
- 不用 `file://`，改用虚拟域 `https://appassets.androidplatform.net/` + `shouldInterceptRequest` 从 assets 读文件
  → 有真正 https origin，localStorage 才稳定持久（`file://` 源在部分机型会被清）
  → 这就是 androidx `WebViewAssetLoader` 的原理，但这里只用 framework API，不引 AndroidX
- 不需要 INTERNET 权限：请求在网络栈之前就被拦截
- `adjustResize` 让软键盘不遮输入框；返回键先 `canGoBack()`

**图标**：改 `build_exe/make_icon.py`，抽出 `draw_wheels()` 复用，新增
- `build_foreground()`：透明底 + 只有车，裁包围盒
- `export_android()`：传统 48dp 五密度 + 自适应 108dp 前景层（车宽占画布 76%，圆形遮罩下不出血）
  自适应背景用 `res/drawable/ic_launcher_background.xml` 的 XML 渐变（#2872F2→#081E58），与 ico 同款

**踩坑**：
1. `javac` 在中文 Windows 默认按 GBK 解码源码 → 中文注释报「GBK 不可映射字符」，必须加 `-encoding UTF-8`
2. 新版 cmdline-tools 里 `sdkmanager` 已废弃，`android sdk install` 才是新命令；且必须给 `--sdk=<path>` 或设 `ANDROID_HOME`，否则 `sdk list` 显示 "no installed packages"
3. `android.bat` 不存在，只有 `android.exe`；`.bat` 要走 `cmd //c` 调用
4. 第一次 `sdkmanager --sdk_root=... build-tools;34.0.0` 静默只装了 platform-tools，必须换 `android.exe --sdk=... sdk install`

**构建入口**：`cd android && python build.py`。脚本开头会从根目录自动同步最新 `车价计算器.html` 到 assets，并复用 `android/debug.keystore`（同一密钥才能覆盖升级）。

**校验**：aapt2 dump badging（包名/版本/minSdk/targetSdk/launcher activity）→ 解包含 assets/index.html、resources.arsc、classes.dex、五密度图标 → dex 里能搜到 `Lcom/nev/pricecalc/MainActivity;` 和 `appassets.androidplatform.net` → apksigner verify 通过（v2+v3）→ sha256 比对 assets/index.html 与源 HTML 一致。

## 推到 GitHub 时踩的网络坑（重要，以后别再查一遍）

本机直连 `github.com:443` 是断的（6 个已知 IP 全超时），但 `api.github.com` 秒通（0.4s）。
原因是环境变量里的 `HTTP(S)_PROXY=http://127.0.0.1:2254` 是 WorkBuddy 内部代理，只放行白名单域名。
**真正能用的是系统代理 `127.0.0.1:7890`**（用户浏览器走的就是它，所以他能建仓库）。

另：命令行的 Git Credential Manager 在非交互 bash 里会卡住不落凭据，
但那次弹窗授权其实有效——用户点完之后，下一次用 .bat 在交互环境跑就直接成功了。

## CI 第一次失败的根因：objectVersion 77

`macos-14` runner 是 Xcode 15，而 XcodeGen 2.44 默认 `projectFormat: xcode16_0`
→ 生成 objectVersion **77**，Xcode 15 直接拒绝：
`could not be opened because it is in a future Xcode project file format (77)`

修法两层：
1. `ios/project.yml` 加 `options.projectFormat: xcode14_0`（XcodeGen 只认这个键，
   没有 `objectVersion` / `compatibilityVersion` 这类选项，别写错）
2. `ios/build.sh` 生成后再兜一层：`grep 'objectVersion = 7'` 命中就 sed 压回 56

没有换 macos-15 的原因：Xcode 16 的 Swift 6 并发检查更严，这套没编译过的 Swift 代码
在 Swift 5.9（Xcode 15）下更容易过，先求跑通。

## 批处理脚本的编码坑（写 .bat 必踩）

UTF-8 编码 + LF 换行 = cmd 把中文按 GBK 拆成半个字符，整行变成「不是内部或外部命令」。
必须：**GBK(cp936) 编码 + CRLF 换行**，且不要 `chcp 65001`。
生成方式：Write 写 UTF-8 源 → PowerShell 读 UTF8 写成 GBK，顺便 `-replace "`n","`r`n"`。

## 最终跑通：CI 秒取消的真正原因 = macos-14 镜像退役

修好 objectVersion 后，push 和 workflow_dispatch **全部在 1 秒内 cancelled**，
而且 `runner_name` 为空、没有任何 step 执行 —— 这不是代码问题，是**分配不到机器**。
排查顺序（都排除了）：仓库 `actions/permissions` = enabled/all、`permissions:` 语法正确、
workflow 没有 `concurrency` 配置、账户没超配额。

真因是 `runs-on: macos-14`，该镜像在 2026 年已进入退役周期。
改 `runs-on: macos-15` 后**一次成功**，Swift 代码零报错。

判据很重要，下次直接照这个特征认：
**run 创建后 1 秒 completed + cancelled + runner_name 空 + steps 为空 = runner 镜像不可用**，
不要把时间浪费在改 workflow 语法上。

## 返息方案从「3 年」改为「5 年返息 / 前 2 年 0 息」（23:05）

原文案「3 年返息 · 前 2 年 0 息」与实际金融产品不符，改为 5 年期（60 期）。

**算法本来就不用改**：`freeN = Math.min(24, n)` + `prinR = loan/n` + 剩余本金按 rate3 摊还，
n=60 时自动就是「前 24 期只还本 → 后 36 期本息」，逻辑天然成立。
实测 157,500 元贷款：月供 `2,625 → 2,790`，总利息 5,925，IRR 2.20%，与手算一致。

真正要改的是**约束与文案**：
- 选项 `3 年返息` → `5 年返息`（保留「前 2 年 0 息」副标）
- 期限与方案绑定：`syncTermLock()` 在 `render()` **开头、read() 之前**调用，
  选返息时强制 60 期并把 12/24/36/48 设 `disabled` + `.is-lock` 置灰；切回其他方案自动解锁。
  （放在 read() 之后会导致本次仍按旧期限计算 —— 这是唯一的顺序陷阱）
- `第 3 年利率` → `第 3–5 年利率`，foot 说明、notes、保存方案标签同步

**两文件同步办法**：标签版是基于原版复制的，改公共逻辑时直接 `cp 原版 标签版` 再重放
segs 那 6 处改动（CSS 块 / segs HTML / modLoan 加 hide / applyTab 块 / 两个 seg-v 赋值），
比在原版和标签版上分别 Edit 更不容易漏。
